## Gaps found & fixed in this audit

### Hub #2 — `/user/password/reset` Mantine (commit `741ee05bb5`)
- **Was:** legacy Pug surface, the only auth page not on the OlliT Mantine
  design system (owner requirement #2).
- **Fix:** `passwordReset.pug` now extends `layout-react` with entrypoint
  `pages/auth/password-reset`; new `pages/auth/password-reset.tsx` renders
  through the shared `OlliTProvider` (AuthCard/AuthField, light scheme,
  system-messages slot — identical surface language as /login + /register).
  The form stays a native `data-ol-async-form` posting to `/user/password/reset`,
  so the server contract (POST + `_csrf`, 6/60s rate limit, optional
  invisible captcha, message bag, sent/not-sent toggle) is untouched by
  construction. New states: email-sent confirmation and
  `?error=token_expired` ("Sorry, your token expired") driven by server meta.
- **Unchanged:** `PasswordResetRouter.mjs` controller — 52/52 PasswordReset
  unit tests pass without modification.

### Hub #6 — `/hub#/mysettings.account` identity fields (commit `90eb890eee`)
- **Was:** account tab rendered "Primary email: —" and empty First/Last
  inputs despite valid DB values.
- **Root cause:** `HubController.buildLocals` fetched
  `User.findById(userId, 'ace')` — a projection of **only** the `ace`
  subdocument — and the hub account tab reads `user.email/first_name/last_name`
  from that meta, so they were always `undefined`.
- **Fix:** project `'ace email first_name last_name'` (keeps `user.ace.*`
  for `UserSettingsHelper.buildUserSettings`; adds the 3 top-level fields).

## Pre-existing findings noted (not regressions, documented)

1. **E2E spec `auth-pages.test.e2e.ts` (login)**: anonymous
   `GET /system/messages` XHR returns 302→/login in the e2e/prod stacks; the
   spec's console filter tolerates the "Failed to load resource … 401" line
   but not the app's own `FetchError: Unauthorized` catch-log line, so the
   spec intermittently fails on that assertion. Introduced with the auth-page
   SystemMessages surface (`36a3331ea2`, prior wave); the page functions
   correctly (login works, no crashes). Harness-filter gap, not a functional
   bug.
2. **Prod login via IP (`127.0.0.1:4000`)**: `POST /login` → 403 by the
   cross-origin guard (`Csrf.blockCrossOriginRequests`) because
   `allowedOrigins` = `OVERLEAF_SITE_URL` =
   `https://psintern.neuro.uni-bremen.de`. Correct behavior — probe prod
   through the canonical hostname, not the port.
