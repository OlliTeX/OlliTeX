## The three defects (verified differential, exact counts)

Classified by probing otc's *actual* output against every mismatching row:

| Class | Defect | Rows |
|---|---|---|
| A | U+FEFF handled as non-whitespace | 3,361 |
| B | Supplementary chars counted per-rune, not per UTF-16 code unit | 23,133 |
| C | Four regex stages missing JS `.` line-terminator guard | 2,140 |
| | **Total** | **28,634** (all mismatches) |

Classification is by precedence (FEFF first, then >U+FFFF, then remainder);
2,140 is exact, not an approximation, and contains **zero** rows lacking any
line-terminator character. Both `clean` and `reason` may diverge on the same
row (the reason string records stage labels only when the string actually
changed).

### Class A — `U+FEFF` is JS whitespace, Go `unicode.IsSpace` misses it

Node: `BAD_FILE_RX = /(^\.$)|(^\.\.$)|(^\s+)|(\s+$)/g` — JS `\s`
**includes** U+FEFF. Go `unicode.IsSpace` does not, so otc `cleanPart`
preserves FEFF in leading/trailing runs instead of replacing each with `_`.

- otc code: `isBadChar`/`cleanPart`, `safe_pathname.go` (uses `unicode.IsSpace`)
- Node source: `BAD_FILE_RX` at `safe_pathname.js:21`

Repro row (fixture idx 2506):
```
input:   \uFEFF                       (U+FEFF)
want:    "_"                            reason "cleanPart", isClean false
otc:     \uFEFF (unchanged)            reason "", isClean TRUE   (WRONG)
```

### Class B — supplementary / surrogate handling is per-rune, not per UTF-16 unit

Node matches `BAD_CHAR_RX = /[/*\u0000-\u001F\u007F\u0080-\u009F\uD800-\uDFFF]/g`
**per UTF-16 code unit**:
- a supplementary char (e.g. U+15238 = surrogate pair `D814 DE38`) is two surrogate units →
  each matches → `__` (two underscores);
- a lone surrogate code unit also matches → `_`.

otc `isBadChar(r rune)` at `safe_pathname.go:25` uses `r > 0xFFFF` per Go rune:
- supplementary rune → **one** `_` (should be two);
- lone surrogate (U+D800–U+DFFF) is **not** flagged (passes through).

- otc code: `isBadChar`, `safe_pathname.go:32`
- Node source: `BAD_CHAR_RX` at `safe_pathname.js:15`

Repro row (fixture idx 6371), UTF-16 code units shown in hex:
```
input:    4E00 15238 0009 0040 1680 002E 0074 0065 0078 000D 2028 4E00
want:     4E00 5F 5F 5F 40 1680 2E 74 65 78 5F 2028 4E00     (U+15238 -> 5F 5F)
otc:      4E00 5F 5F 40 1680 2E 74 65 78 5F 2028 4E00       (U+15238 -> only one 5F)
```

Note also `IsCleanDebug`: `len([]rune(pathname)) > maxPath` counts runes;
Node's `pathname.length` counts UTF-16 code units (a supplementary char is 2).

### Class C — four stages rely on JS "`.` does not match line terminators", otc uses unconditional string ops

Node `cleanDebug` stages:
```js
pathname = pathname.replace(/^(\/.*)$/, '__$1' /* "_$1" */);   // no leading /
pathname = pathname.replace(/^(.+)\/$/, '$1');                // no trailing /
pathname = pathname.replace(/^ *(.*)$/, '$1');                // no leading spaces
pathname = pathname.replace(/^(.*[^ ]) *$/, '$1');            // no trailing spaces
```
V8 `.` does **not** match U+000A, U+000D, U+2028, U+2029. If the string at
that stage contains **any** of those four characters, each anchored regex
fails to match and the stage is silently skipped (no replacement, no reason
recorded). `\r`/`\n` are still present at this point (they are replaced later,
in `cleanPart`), so they trigger the guard too.

otc does unconditional `HasPrefix("/")`/`HasSuffix("/")`/`TrimLeft(" ")`/
`HasSuffix(" ") && TrimRight(" ")` → diverges whenever a line terminator is
present.

- otc code: `CleanDebug` guard stages at `safe_pathname.go:170–192`; `allSpaces` at `safe_pathname.go:212`
- Node source: `safe_pathname.js:97–107`

Repro rows (hex UTF-16 code units; LSEP = 2028, CR = 000D, NBSP = 00A0):

## The fix (spec)

Reproduce the reference implementation's semantics — full known-good source at
`git show a8a67f3:services/clsi.go/ot/safepathname.go` (operates on `[]uint16`):

1. **Operate in UTF-16 code units** throughout (`cleanPart`, stage functions,
   `MaxPath` length check). Node is unit-based everywhere.
2. **`isBadChar(u uint16)`**: `u=='/' || u=='*' || u<=0x1F || u==0x7F ||
   u>=0x80 && u<=0x9F || u>=0xD800 && u<=0xDFFF`. (Each surrogate unit is its
   own match → supplementary char becomes `__`.)
3. **Whitespace set** for leading/trailing runs: JS `\s` minus the members
   already consumed by `BAD_CHAR`. The only reachable difference vs
   `unicode.IsSpace` is **U+FEFF (must be treated as whitespace)**. Full JS
   `\s` (for reference): `{0009–000D, 0020, 00A0, 1680, 2000–200A, 2028,
   2029, 202F, 205F, 3000, FEFF}`.
4. **Line-terminator guard** on the four stages (no leading `/`, no trailing
   `/`, no leading spaces, no trailing spaces): skip (no change, **no reason
   recorded**) when the current string contains U+000A, U+000D, U+2028 or
   U+2029. The "no trailing spaces" stage additionally requires a
   non-space content char before the trailing run (Node's `[^ ]` in `.*[^ ]`);
   the "no leading spaces" stage trims the leading 0x20 run only.
5. **`IsCleanDebug` length check** counts UTF-16 code units, not runes.
6. Keep exported signatures: `Clean(string) string`,
   `CleanDebug(string) (string, string)`, `IsClean(string) bool`,
   `IsCleanDebug(string) (bool, string)`.

The reference implementation passed 80,782/80,782 on all five fixture fields
(verified freshly against this exact fixture before the port was deleted).
