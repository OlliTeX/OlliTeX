# /hub + /editor bug hunt — 2026-09-09

Owner request (overnight mandate, 07-09): after the renovation phases, run a
bug hunt for /hub and /editor. Executed 2026-09-09 on the P2 image
(`9508fe5ad730`, ext-6.3.0-port) — e2e stack `127.0.0.1:7420` (all three
roles, light + dark), production verified at route/asset level
(`127.0.0.1:4000`, same image, /editor + /Project + /login contracts).

## Method

- **Round 1** (surface sweep): 18 hub sections (10 admin, 8 user) + both
  editor routes — console/pageerror/5xx capture, axe-core per section,
  i18n scan, menu/compile/file-tree/history walks. (`specs/bug-hunt.test.e2e.ts`)
- **Round 2** (deep flows): hub project create, template gallery, settings
  round-trips, admin user create, system messages, editor file create/rename,
  settings modal, command palette, history. (`specs/bug-hunt-r2.test.e2e.ts`)
- **Rounds 3-5** (verification probes): every round-2 red re-tested against
  the real UI semantics (correct hub route names, real control affordances,
  correct form targets). All five round-2 reds proved to be **probe
  artifacts**, not app bugs — each flow verified green end-to-end with the
  correct locators (project created + listed; settings name persisted;
  admin user created + listed; file created in tree; menus/compile clean).

## Findings (severity-ordered)

1. **[med, FIXED in this wave] hub-a11y suite flake (false reds)** —
   `spec/parity/hub-a11y` intermittently reported `color-contrast` on
   `site.general.health/.stats/.users.all` (Mantine light-badge labels).
   Root cause: **axe sampled during section hydration** (badge painted on
   the pre-section default background). Direct runs of the same sections
   show zero violations. Fix (committed): the spec now waits for
   `networkidle` + settle before `analyze()`; 11/11 ×3 consecutive runs
   (workers=2). Not an app defect — no user-visible bug.
2. **[low] hub unknown-hash silently falls back** — `#/settings`,
   `#/admin/users` (invalid leaf names) render the default section
   (projects/site default) with no "section not found" hint. URL typos are
   easy to hit (real leaf names are `mysettings.*`, `site.general.*`).
   Suggestion: a gentle "Unknown section: `<hash>`" state instead of the
   silent fallback. (Cosmetic/UX — queued, not fixed yet.)
3. **[info] command palette (Ctrl+K) intentionally off** — the palette
   component + action exist (`kb_command_palette`) but the
   `command-palette` feature flag is off in this 6.3.0 build, so Ctrl+K is
   inert and no UI entry exists. Baseline behavior, not a regression.
4. **[info] hub modals (New project, New user) render their shell first,
   inputs ~1-2s later** — an impatient early click on "Create/Copy" hits
   empty-form validation. Harmless but slightly clunky; consider rendering
   the form inputs synchronously with the modal header. (Cosmetic — queued.)
5. **[info] editor default layout hides the PDF pane** — "no PDF pane
   after compile" in the default (editor-only) layout is *by design*; the
   P2 layout-toggle contract test proves the split layout + PDF pane work.
