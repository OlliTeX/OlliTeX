### ✅ O2 PARITY GAP AUDIT + typstEnabled DECISION (RECORDED) (2026-10-02)
Audited the specific O2 claims against the Node oracle (`services/web/app/src/infrastructure/ExpressLocals.mjs`):
- **typstEnabled**: Node exposes `typstEnabled: !!(Settings.typst && Settings.typst.enabled)` (ExpressLocals.mjs:530) ⇒ config-driven from `COMPILE_TYPEST_ENABLED` (default ON). Go exposes `typstEnabled:true` (pinned). 
- **safeCompilers**: Node does NOT put `safeCompilers` in `ol-ExposedSettings` — it's an internal Node-server setting (`ClsiManager.mjs:40 VALID_COMPILERS`, `ProjectOptionsHandler.mjs:18`). The frontend compiler dropdown (`compiler-setting.tsx`) uses a STATIC list gated on `typstEnabled`, never reading `safeCompilers` from exposed settings. ⇒ **No parity gap**: Go's parity is exposed `typstEnabled` + service-side compiler validation (`clsitypst` `validCompilers=["typst"]`) + web dispatch typst→:3014.
- **`.typ`/textExtensions/validRootDocExtensions**: all present in both Node + Go exposed settings ✓.

**DECISION (honest-oracle, recorded):** Go PINS `typstEnabled:true` in the shipped exposed settings. This matches Node's live behavior because (a) `COMPILE_TYPEST_ENABLED` defaults ON, (b) the runit flip sets `COMPILE_TYPEST_ENABLED="${COMPILE_TYPEST_ENABLED:-true}"`, and (c) the owner's binding intent is "Typst is a first-class ALWAYS-ON feature". Making it config-driven (honoring a `COMPILE_TYPEST_ENABLED=false` toggle) is a FOLLOW-UP only if the owner ever wants to disable Typst at the web layer (currently that contradicts the stated intent and risks hiding the crown jewel); not needed for this arc. Recorded here rather than left as an open "needs decision".
