## User story (owner-specified 2026-10-11)
Build Playwright e2e specs — one per engine — that mimic **complex real editing behavior**, trying as many editor functions/combinations as practical:

1. **Create a project** (TeX: blank sample; Typst: new-project-menu typst option).
2. **Edit it richly** in the editor:
   - **Lorem text** generated with the PyPI package `python-lorem-ipsum` (deterministic seed) — substantial multi-paragraph body.
   - **External images** from `docs/ub-logo/` (logo.svg, logo_full.svg, logo_sw.svg) uploaded into the project via the file-tree upload; used in the doc (`#image("…svg")` in Typst — native; in TeX via graphicx PNG (convert SVG→PNG in fixture pipeline) and/or the `svg` package if the sandbox supports it).
   - **Equations**: LaTeX equations drawn from `tests/e2e/test-data/im2latex-100k/im2latex_formulas.lst` (103,558 lines, physics corpus; select ~30 cleaned display/inline ones → fixture). For Typst: a converted subset (frac/sqrt/sum/int/greeks → Typst math) plus Typst-native math features.
   - **Use many editor functions**: multi-file project (second .tex file in a subfolder + \input), insert equation/table via Insert menu, search-in-file, rename, compile via toolbar, PDF output assertions.
3. **References (owner-specific)**: import **some of the owner's ORCID works (ORCID iD 0000-0002-8819-4879)** into the test project as test references **via the bib visual editor** — i.e. the spec opens the `.bib` file, uses the visual-References UI to add/pin the entries, `\cite` + `\nocite{*}` in main, compile, and the PDF shows the reference list.
4. **Compile** and assert: no error toast, PDF generated non-empty (size threshold / page count if tooling available).
