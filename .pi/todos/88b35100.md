What was WRONG in my earlier probe: I tested the wrong URLs.
- GET /project/:id → 404   = the OLD per-project landing/file-list page. This route was DELIBERATELY retired in the earlier route-retirement work (TODO-bbc3e745: "Retire legacy /Project/:id editor PAGE route, keep /editor/:id + /Project/:id APIs"). In this build the project list lives in the HUB; there is no /project/:id landing page. Not a regression.
- GET /project/:id/editor/main.tex → 404 = not a real route shape in this build.
- GET /project/:id/docs/main.tex → 404 = not a real doc endpoint.

What ACTUALLY works (live-verified):
- POST /project/new → 200 {project_id}; the new project DOES get a seeded main.tex (ollitex.docs has the doc; project.rootFolder present). create.go (P4.7) seeds rootFolder + main.tex + docstore revision 0 correctly.
- GET /editor/:pid → 200, renders the real editor (body has .cm-editor, title "<name> - Online LaTeX Editor OlliTeX"). This is the canonical editor route and where the hub links the project.

Conclusion: NO bug. The editor is reachable and seeded correctly. The only real residual is the DELETE /project/:id I used to clean up returned 404 (cleanup path shape differs), which is an incidental test-harness issue, not an app defect. Closing as not-applicable.
