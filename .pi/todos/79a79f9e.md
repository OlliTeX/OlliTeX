## Reproduction + root cause (probes: /tmp/pp/ab_*.cjs, all against psintern.neuro.uni-bremen.de project menuverify 6ac9175e59fa4f310c3868cc)
The drawio integration pipeline EXISTED and is mostly sound (modules/drawio provider claims .drawio, defaultVisual, vendored same-origin app at /static/drawio indexed clean, hash protocol host↔iframe). What actually broke owner experience:

1. **THE BUG (fixed v20): the Code|Visual switch vanishes exactly when you need it.** The switch (source-editor/components/editor-switch.tsx) is rendered ONLY inside the CodeMirror toolbar (toolbar-layout.tsx → .ol-cm-toolbar inside .cm-editor). When the visual editor is active, CodeMirrorView gets `hidden` → the whole .cm-editor subtree (toolbar + switch) is display:none → switch measured 0x0 in visual mode → user is STUCK in the canvas with no way back to source (and vice-versa, the toolbar switch is the only exit from code). Fixed: `drawio-viewer.tsx` now mounts EditorSwitch in its own always-visible `.drawio-viewer-toolbar` row (+ `.drawio-viewer-switch { margin-left:auto }` in drawio-viewer.css). Same EP-context driven state — no duplication issues (the hidden copy is display:none).
2. **Misrouted edits risk during races**: several probe sessions showed edits landing in the OTHER doc (main.tex received diagram XML; fig.drawio kept an HTML comment). Cause: my puppeteer scripted typing targeting the first .cm-content while the auto-open(last-used doc)+first-click flow was mid-race; the app's OWN paths (context-bound CodeMirrorView writes; iframe hash poll → writeDoc through useCodeMirrorViewContext) always land in the correct doc. Data restored (below).
3. **Deployment trap (owner-visible risk!)**: `toolkit/.env` pins `WEB_IMAGE=ollitex/ollitex:main`; compose gives the shell env precedence in our flow BUT one recreate in this turn was missing the `WEB_IMAGE=` prefix and silently swapped the dev server to the old 15h-mainline image (308-frozen-dist). Detected by runtime-hash mismatch (repo/mainline `runtime-7ec448fb…` vs my builds `runtime-321c…`/`runtime-2c15…`). Fixed: redeployed with `WEB_IMAGE=olpsint/overleaf:g-2026-10-09-v20`; verified `docker inspect` = v20 image, live runtime 2c15b8b4 = 200. LESSON: after every compose up, verify `docker inspect ollitex-web --format '{{.Config.Image}}'` AND the live runtime chunk hash.
