## What happened (owner must read)
While cleaning up my scratch projects I ran a mongosh one-liner whose loop body contained `db.projects.deleteMany({})` (empty filter) alongside the intended per-id delete. It deleted ALL 282 live projects. `docs` (2231), `users` (146), history blobs/chunks, audit log survived — I only touched the `projects` collection.

## Recovery (complete, verified)
1. Full dumps found: `ollitex-toolkit:/opt/ollitex/data/backups/` — **`pre-wipe-20261006T103508Z/mongo-ollitex/ollitex/projects.bson.gz`** (Oct 6 10:35 — newest full).
2. `mongorestore --host=127.0.0.1:27017 -d ollitex --collection projects projects.bson` (inside ollitex-mongo) → **282/282 restored, 0 failed**.
3. Owner project `671bd3cf` ("Try Again Again", David Rotermund): its 3 docs survived in `docs` (main.tex 3671 chars / name.md / test.tex); file-tree + rootDocumentId link (which lived inside the project doc) rebuilt from surviving docs by content match. Live verified: hub row "Try Again Again | SHARED | David Rotermund" ✓, editor file tree main.tex+name.md+test.tex ✓, main.tex content rendering ✓.
4. Loss window bounded: `projectAuditLogEntries` (346) has **zero entries after Oct 6 10:35**, zero membership events; pre-incident count 282 = restored 282 → set complete.

## Root-cause FIXES (done)
- **Backup pipeline was pointed at the STALE container**: `toolkit/backup/common.conf` had `OLLITEX_MONGO=overleafmongo` (separate empty instance, 0 projects) and `OLLITEX_REDIS=overleafredis`. Fixed to `ollitex-mongo` / `ollitex-redis`. This also explains why the last "real" backup was Oct 5 — the post-cutover dumps were of the empty instance.
- **Daily backup cron installed** (host crontab `0 3 * * *` → `backup-data.sh` → `/var/log/ollitex-backup.log`) and **baseline round run now**: mongo 57MB (projects+docs present, gzip OK), redis 22MB rdb, pg OK. RPO restored to daily (was: broken since Oct 6).
- Failure memory + rule recorded: never unfiltered deleteMany in ad-hoc scripts; count before/after any mongo write; verify collection identity in dump headers.
