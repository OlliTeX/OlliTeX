## DONE — battery 37/37 ALL GREEN ×3 (tk1 18 + tk2 14 + tk3 5), final image live

### Root causes found + fixed (via TK_TRACE + targeted repros)
1. **H3 (boot death at any size ≠80x24)** = tcell v2.8.1 `tScreen.Init()` NOT idempotent: 2nd Init (our explicit + tview SetScreen) shrinks the cell buffer to terminfo-default 80 wide while the screen stays 80+ wide → `drawCell(col 80)` returns width 0 → `x += -1` infinite render loop. Exactly 80x24: shrink no-op → survived. **Fix: `onceInitScreen` wrapper (Init-once)** in `SessionScreen()`; regression test `zz_repro81_test.go` (all sizes, byte-counted). Live-verified 40x12 … 200x50.
2. **H2/S14 digit lag** = (a) `settingsNav` level-0 fall-through `return !handled` (always true) swallowed digits 1-9 from the Settings screen; (b) `openScreen` started the async job BEFORE the navigation redraw. **Fix: `return false`; redraw-before-job** (`ui.go`).
3. **Battery flake class (T5/T12/S2/S3/S11/S14)** =
   - queued renders (`go QueueUpdateDraw`) run only when tview's select picks the updates channel — under rapid keys they can land AFTER the next screen switch → stale frame. **Fix: `inLoop` flag — render INLINE inside key-capture (tview paints after capture anyway); `requestPaint()` skips the redundant queue call.**
   - shells screen key is **Enter** (or x1..x4) — bare digits are global screen jumps — + mongosh banner slow cold + battery CPU contention (killed sessions leave in-flight compose/pull jobs running up to their 180 s timeout). **Fix: `pollFor` pollUntil in the harness; S11 uses Enter; S2/S3/T5/T12 poll for the dialog/pane instead of fixed windows.**
   - T12 [n]-button coords re-measured: modal 25,3 30x17 → **[n] at screen (46,19), [y] at ≈(33,18)** (a [y] hit = stack actually stops — verified by status text).
4. tview mouse chain verified in trace: root wrapper → Modal(Box) → Form → Button; `consumed=true` only when a button (or the form fallback) fires.
