## FIXED (2026-10-11) — ag-v53, live-verified, 17/17 + 8/8 e2e

ROOT CAUSE (confirmed by code walk): the build content plane (Go docstore)
is filled by the collab room→docstore write-through (writeback.go), which
is DEBOUNCED 1.5s after the last room update and flushed on room-unload.
A build dispatched inside that window (Edit → Recompile, the editor's own
button, session open) silently compiled PRE-EDIT content. The
`POST /project/:id/flush` endpoint is a V2 pass-through with no Yjs
producer and was never wired. (The 'no resources'/seed windows are the
same family; seeds do land in the docstore at project create — reproduced
clean.)

FIX (commit 1959dab4):
- collab (cmd/collab/main.go): new internal endpoint `POST /flushroom`
  (same internal-port convention as /presence + /metrics; edge does not
  forward it; validates room names via collab.ValidRoomName; flushes each
  room head NOW via WriteBack.FlushRoom — room head is read from the
  version store, so it works with or without a live in-memory room).
- web (compile.go): compile handler flushes the project's rooms (root doc
  + every per-doc room from the project tree) BEFORE reading the docstore
  lines. Fail-soft by contract: 8s timeout / collab outage logs and the
  build proceeds with today's behavior — a flush never kills a build.
- .gitignore: the bare legacy `collab` artifact pattern was silently
  gitignoring cmd/collab/ + go/services/collab/ (tracked Go service) —
  anchored to the repo root (/collab).
- go/services/collab/presence.go (AJ-3) was in the worktree but NEVER
  committed (binaries only built on hosts where the file happened to
  exist) — now committed.
- spec T1b upgraded to assert BOTH directions fresh (post-fix contract).
