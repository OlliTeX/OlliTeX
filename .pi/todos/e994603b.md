## e2e: AUTH lifecycle (password reset cycle, registration, mail outbox) — today login + preference surfaces are pinned, the FULL auth flows are not

Owner audit 2026-10-11.

Current: auth-pages + consent + sso + email-templates pin the SURFACES (render + 404 retirement + the BYO-LLM key round-trip). The CONNECTED flows are untested: forgetting a password end-to-end, registering a new user, and the mail artifacts of both (smtpsink capture).

Legs:
1. **Password reset cycle (the big one)**: user triggers "forgot password" (auth-pages surface) → smtpsink captures the mail → parse the reset LINK from the body → open the link in a fresh context → set a new password → old password no longer works (wire negative), new password works (fresh login) + a NEW session is issued (old token invalidated — pin actual behavior: discover first).
2. **Reset link hygiene**: the link is single-use (or time-bounded — pin whichever) → a second use of the same link is REJECTED; a malformed/truncated token → 404/400, not 500.
3. **Registration** (if enabled on this revision — discover the site-settings gate first; CE has a "new users may sign up" toggle): signup form → confirmation mail (smtpsink: if the product sends it) → login with the new credential → the new user appears on the admin surface (connected leg) + the admin can disable signup → the form 404s/hides (pin whichever).
4. **Password change from own session** (user settings → password, if exposed): change → forced re-auth or session continuation (pin actual behavior) + old password rejected.
5. **Mail outbox assertions**: every flow that emits mail leaves a parseable message in smtpsink with the correct recipient + a functional deep-link (the invite-mail link is pinned elsewhere; this pins the reset/registration mails).

Standing facts: smtpsink = e2e compose service (mail capture; parse raw RFC822 or use its HTTP surface if exposed — discover); the email-templates spec shows the template pin pattern (reuse); auth surface routes in go/services/web/features/authpages + passwordreset + registrationpage; CSRF; rate-limit: password reset may have its own throttle (pin the throttle if present — negative leg: 5th rapid request → 429/403, then backoff); base http://127.0.0.1:7420 (ag-v46).

Exit: green specs (auth-password-reset.test + auth-registration.test + auth-mail-outbox.test), auth-pages + email-templates re-run green, commit + close with evidence.
