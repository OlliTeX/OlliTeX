## Context
The history panel's per-change diff (`features/history`) expects Node/V2 diff chunks to carry
per-chunk `meta { users[], end_ts }` for the "Added by X / Removed by X on date" highlights.
The Go Yjs diff plane (`go/services/web/features/history/yjsdiff.go`, `yjsUpdates`,
`buildUnifiedFeedMulti`) emits `{"i": ...}` / `{"d": ...}` chunks WITHOUT meta — the panel
hard-threw ('No meta found') and the whole view crashed until 45009469 (graceful degrade:
neutral "Added/Removed" labels, anonymous hue).

## Work (when picked up)
1. `yjsDiff` / the unified feed already knows per-version `meta` (users, start_ts/end_ts —
   see the /updates body shape) — thread the attribution of each diff hunk back to the
   version(s) it came from (from→to range) and attach `meta` to the chunks (match the Node
   contract: users = contributor(s), end_ts = version ts).
2. The frontend already consumes meta when present (highlights-from-diff-response) — no FE
   change needed beyond dropping the fallback labels.
3. E2E: extend specs/history-versioning T1/T2 to assert `meta.users` non-empty on
   single-user diffs and per-author attribution in the T5 two-user diff.
