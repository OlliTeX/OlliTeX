**Date:** 2026-09-30
**Repo:** `/home/davrot/shb/OlliTeX_shb` (Go services under `go/`, `cmd/`; shared libs; TS/React frontend)

## CRITICAL

### C1. Runtime panic — invalid regexp `\u` escape kills the web process (DoS)
**File:** `go/services/web/features/llmsettings/compliance.go:434`
```go
bullet := regexp.MustCompile(`^\s*[-*\u2022]\s+`)
```
Go's RE2 engine does **not** support `\u` escapes in a raw string, so
`regexp.MustCompile` panics with `error parsing regexp: invalid escape sequence:
'\u'` (reproduced verbatim with a standalone program). This runs inside
`chSplitRubric` (called at line 571 from `chPerform`), which is launched as a plain
background goroutine from the HTTP handler (`go f.chPerform(ctx, job)`, line 371)
after a `200` has already been sent.

There is **no `defer recover()`** protecting that goroutine. In Go, a panic in a
*plain* goroutine (not net/http's per-connection goroutine) **crashes the entire
process**, not just one connection (verified empirically — the server dies and all
subsequent requests fail). So a single
`POST /project/:id/llm/compliance/start` that reaches the rubric-split path
terminates the whole web service.

- Reachability is gated by `featureFlags()["reviewEnabled"]` (default true, see
  `admin.go:187,243`) and a configured LLM lane (`resolveLane`). When those are on —
  the product default for the LLM review feature — this is a one-POST DoS.
- **Fix:** (a) compile the regexp at package `init` (fail-fast, once), and
  (b) write the bullet char as `` `^\s*[-*\x{2022}]\s+` `` (RE2 accepts `\x{…}`), and
  (c) add a guarded `recover()` in `chPerform` that reports the error via
  `chFinish(…, "error", "internal", …)` so a future compile error degrades to a
  failed job rather than a process crash.

### C2. Open redirect — `POST /logout` forwards attacker `Redirect` with no validation
**File:** `go/services/web/features/authpages/authpages_logout.go:30-34`
```go
target := body.Redirect
if target == "" { target = "/login" }
res.Redirect(cxt.Req, 302, target)
```
`body.Redirect` is taken straight from the JSON body and passed to
`http.Redirect(302, …)` with **no same-origin / scheme check**. `core.Res.Redirect`
(`go/services/web/core/response.go:159-200`) also echoes the URL verbatim into the
response body (`"<p>Found. Redirecting to " + url + "</p>"`), so a
`javascript:`/cross-origin redirect is reflected.

Exploitation requires the victim's `_csrf` token (all POSTs are CSRF-gated), so this
is not a trivial cross-site open redirect, but the framework already has a validated
login-time redirect (`authpages_login.go`) it should reuse. **Fix:** reuse the
login redirect validator (relative path only), never accept absolute / protocol-relative
URLs or `javascript:`.

### C3. Hand-rolled Redis client — single connection + global mutex + no I/O deadlines
**File:** `go/services/web/core/redis.go`
- One `net.Conn` behind a single `sync.Mutex` (line 179). Every session load/save,
  rate-limit, cache, and CSRF-secret op **serializes through that one connection**.
  A slow / hung Redis stalls *all* web requests in the process.
- No `SetReadDeadline`/`SetWriteDeadline` anywhere; `readReply` blocks unbounded.
- `Close()` (line ~243) reads/writes `r.c` **without** the mutex → data race with
  `command()`/`commandNoLock` (would be caught by `go test -race`).
- `SCAN` is capped at 10000 iterations (line 469) → silent key-set truncation.
- **Fix:** use `github.com/redis/go-redis/v9` (connection pool + `ReadTimeout`) or at
  minimum add deadlines and a `sync.Once` close.

### C4. datamanipulator service is unauthenticated by default + permissive file modes
**Files:** `cmd/datamanipulator/main.go:32`, `go/pbhttp/gate.go:51-64`,
`go/libraries/datamanipulator/fileops.go:100-103`
- `AuthGate(next, expected, …)` **falls through to open access** when
  `SHARED_SERVICE_TOKEN` is empty (it only logs a warning once via `sync.Once` and
  returns `next.ServeHTTP`). The service listens on `:4001` (all interfaces) by
  default.
- With no token, anyone who can reach port 4001 gets **full project file read/write/
  delete/tree**: `GET|POST|DELETE /file`, `GET /tree`, `POST /pull`.
- Path guard is lexical only (`filepath.Abs` prefix check) — **symlinks are not
  resolved** (`EvalSymlinks` is not used), so a pre-seeded symlink inside the project
  dir escapes the sandbox.
- Files written `0o666`, dirs `0o777` (`fileops.go:100-103`) — world-writable.
- **Fix:** default-*deny* (503) when the token is unset and this is not explicitly a
  local dev mode; resolve symlinks after the prefix check; bind to `127.0.0.1` unless
  explicitly configured.

## HIGH

### H1. pgx v5.7.5 — SQL injection via dollar-quoted placeholders (repo-reachable)
**File:** `go/services/historyv1/chunkstore_pg.go:466`
govulncheck reports a **reachable** trace: `historyv1.pgBlobMeta.Clone` →
`pgxpool.Pool.Query` → `sanitize.SanitizeSQL` (`GO-2026-5004`). Two more pgx vulns
(GO-2026-4771 / 4772, CVE-2026-33815/16) are also present but not reachable from this
code. **Fix:** bump `github.com/jackc/pgx/v5` to `>= v5.9.2`.

### H2. E2E fixtures (incl. literal `_csrf` tokens) baked into production HTML
**Files:** `go/services/web/views/pages_data_p2.go` (constants
`passwordResetHTML`, `setPasswordHTML`, `tokenAccessLegacyHTML`,
`sharingUpdatesHTML`), `pages_data_p3c.go` (`settingsHTML`, `sessionsHTML`),
`pages_data.go`.

The view HTML is *captured* from e2e runs and committed as Go string constants.
Byte-level inspection (see verification below) shows that several `<input name="_csrf"
…>` forms carry **hardcoded literal tokens** — e.g. `kqYCGy4j-ONpvNUHE2zYTR4ObW-LAy0cjEiQ`,
`3XOEqz0Z-13MTXD-X-3Q4CjCo27Qh2w0ZXwo`, `VmzhMtSC-6M1kHvAlhoGrLeLiSVq9YU2Jxpw` — that are
**not** wrapped in the runtime `\x01CSRF\x02` slot. `finalize()` only substitutes
`slotCSRF` (`\x01CSRF\x02`) from the *current* session token; these literals pass
through unchanged and are served as-is.

Because the CSRF secret is **per-session** (`go/services/web/core/app.go:445`
verifies against `sess.CsrfSecret()`), a baked e2e token will not verify against a real
user's live session → those forms return 403 CSRF on POST. The same bake also ships
`e2e-user@e2e.test`, project id `6aa4b8c973ef0e5094f4cc02`, and origin
`http://127.0.0.1:7420` to real users (info disclosure).

- **Confirmed:** the literal tokens bypass `finalize` (they are not the slot) and the
  secret is per-session.
- **Needs live confirmation:** whether the hydrated React auth surface re-rewrites the
  `_csrf` field before submit (the static form is the source the async-form engine
  hydrates from; `hydrate-form.ts` does not itself touch `_csrf`). Either way the
  e2e user/project/origin values are a guaranteed info leak and the baked tokens are
  dead weight / potential CSRF failure.
- **Fix:** regenerate the captured pages with a slot for each `_csrf`, `ol-user`,
  `ol-project_id`, and origin instead of baking literals.

### H3. Reflected CORS + `Access-Control-Allow-Credentials: true` on the realtime bus
**File:** `go/services/realtime/server.go:138, 635-638`
```go
wsUpgrader: websocket.Upgrader{CheckOrigin: func(*http.Request) bool { return true }},
// cors():
w.Header().Set("Access-Control-Allow-Origin", o)   // echoes arbitrary Origin
w.Header().Set("Access-Control-Allow-Credentials", "true")
```
Applied to handshake, polling, and socket.io bundle endpoints (call sites 183, 371,
456). Auth is enforced later via the session cookie + `Web.Join`, so this is not an
open-join; but echoing any `Origin` with credentials allows cross-origin credentialed
reads of session-bearing endpoints. **Fix:** origin allowlist, or at least do not emit
`Allow-Credentials: true` for mismatched/absent origins.

### H4. Non-constant-time basic-auth credential compare
**File:** `go/services/web/core/privateapi.go:107, 150, 197`
```go
if eu != "" && au == eu && p == ep {   // == on user and password
```
Contrast: `pbhttp.AuthGate` correctly uses `TimingSafeEqual` and the session-cookie
verify uses `ConstantTimeCompare`. A timing side-channel is feasible on the Web-API
basic-auth path. **Fix:** `subtle.ConstantTimeCompare` for both user and password.

### H5. `panic(err)` on Mongo error in the one-time-token path
**File:** `go/services/web/core/tokens.go:38`
```go
db, err := o.DB.DB(ctx)
if err != nil { panic(err) }   // "unreachable in the wired deployments"
```
Any Mongo hiccup during a password-reset / one-time-token operation panics the web
process. **Fix:** return `(nil, err)` and let the caller surface a 500.

### H6. Postback signing key logged in plain text (Debug level)
**File:** `go/services/gitbridge/bridge/bridge.go:462`
```go
wglog.Debug("[%s] Created postback key: %s", projectName, postbackKey)
```
`postbackKey` is a credential for snapshot approval. Even at Debug level it can be
shipped to ELK/Grafana and retained. **Fix:** log a masked prefix only.

## OPTIMIZATION

### OPT1. Redis client → `go-redis/v9` pool (see C3/H3)
Removes the single-connection serialization and the missing deadlines. Largest
throughput win on the hot path.

### OPT2. Single-pass view rendering (see M8)
55 `strings.ReplaceAll` per request ≈ 55 full-string copies. A single-pass
slot writer is a ~30% memory/reduction win on every HTML page.

### OPT3. `dmWalkTree` reads whole files into memory
`go/libraries/datamanipulator/…` checksums + type-detects each file by full
`os.ReadFile`. A 10 GB project allocates ~10 GB. **Fix:** stream with
`io.Copy` + `sha256` in chunks, and detect type from `os.Stat`/header bytes before
opening.

### OPT4. 18k lines of generated Go committed (see M9)
`nfdbase.go` (13.8k) + `escape_table.go` (4.7k) bloat the binary and `go build`.
Generate at CI and keep headers.

### OPT5. Dead code (U1000, see M3)
Removing 100 dead symbols shrinks compile time and attack surface.

### OPT6. Realtime CORS: consolidate 3 handler call sites
Fold `cors()` into one `cors.Handler` middleware; avoid triple `Header().Set` per
request (also a precondition for the H3 fix).

  `NetworkDisabled`, `CapDrop ALL`, seccomp profile, `NoNewPrivileges`. Well hardened.

  anti-race.

- **Realtime `Connect`** — session + `Web.Join` project-access check (not open-join).
- **`pbhttp.AuthGate`** — constant-time token compare.
- **Config DB** — deliberately secret-free.
- **Frontend** — 0 `eval`.
