## Real bugs found this round — ALL FIXED & RE-PROVEN (6)

| # | Surface | Violation | Root cause | Fix |
|---|---------|-----------|-----------|-----|
| 1 | Settings modal (both routes) | `aria-required-children` | tab `Nav` is `role=tablist` but mixes in non-tab anchor entries | `role="region"` on the settings tab nav (`settings-modal-body.tsx`) |
| 2 | History diff editor (both) | `aria-input-field-name` | diff CM6 contenteditable has `tabindex=0` and no accessible name | `aria-label` via `contentAttributes` + new key `history_diff_readonly` (`document-diff-viewer.tsx`, `locales/en.json`) |
| 3 | /editor Mantine modals, dark scheme | `color-contrast` (title, invite-label, links) | portal renders **outside** the app's theme scope → raw OL tokens resolve to light values on the dark shell (2.6:1) | enforce the documented "modals stay light" contract on `.ol-mant-modal`: light themed token re-anchor + Mantine content bg + close-btn color keyed off `html[data-mantine-color-scheme]` (`modal.scss`) |
| 4 | Mantine modal close (both) | `button-name` | Mantine 9.6 has **no runtime** `closeButtonAriaLabel` prop (type exists, runtime drops it) | `closeButtonProps={{ 'aria-label': t('close_dialog') }}` (`ol-modal.tsx`) |
| 5 | Toolbar dropdowns (both) | `aria-allowed-attr` (menuitem) | react-bootstrap `Dropdown.Item active` injects `aria-selected`; layout options also passed invalid `aria-current` | `OLDropdownItem` renders the `active` **class** instead of the RB `active` prop; dropped `aria-current` (`ol-dropdown-menu.tsx`, `change-layout-options.tsx`) |
| 6a | History toggle + meta (dark, /editor) | `color-contrast` 2.59–2.78:1 | dark theme's `--content-secondary-dark` (neutral-20) below 4.5:1 on mid-dark surfaces | active toggle track bumped to `--bg-accent-02` (white text ≥6:1, `toolbar.scss`); dark-scheme history meta text → primary themed token (`history.scss`) |
| 6b | /admin-hub footer (admin) | `link-in-text-block` ×2 | attribution links visually identical to sentence text — in the **PUG** footer (not the React one) | `.site-footer-attribution-link` underline + themed link color (`thin-footer.pug`, `footer.scss`, React twin) |

### Notable traps hit (for the record)
- **Mantine 9.6 `closeButtonAriaLabel`**: TS types accept it, runtime
  destructures only `closeButtonProps` — the prop silently no-ops.
- **`docker cp dir container:/dir`** copies *into* the target (created
  `app/app`); use `docker cp dir/. container:/dir`.
- **`locales/en.json` is data**: a single malformed edit broke i18n
  app-wide (raw keys in every view) — caught by E2E immediately; JSON
  object shape is load-bearing.
- **PUG layouts are precompiled** to `views/**/*.js` in the image —
  template edits need the compiled artifact or a rebuild, not just the
  `.pug` file.

## Known / documented (not fixed — design decision)

- **Dark theme secondary token** (`--content-secondary-dark` = neutral-20
  `#8d96a5`) is ~2.6:1 on the instance's mid-dark surfaces. The legacy
  `/Project` history surface passes only because of its light-forced
  scoping. A global token bump (neutral-20 → lighter) would lift every
  dark-scheme secondary text — flagged for a design/owner decision,
  deliberately **not** changed unilaterally (app-wide visual identity).
- MathJax/CDN console errors in the offline e2e sandbox — environmental,
  benign (filtered as such in the suite).
